# Public Review Manifest

Use this manifest as the handoff packet for the sparse voxel refactor. It lists
the tracked docs, commands, generated artifacts, and remaining limits reviewers
should expect.

## Review Commands

Run from the repository root unless noted otherwise.

| Purpose | Command | Expected Evidence |
| --- | --- | --- |
| Build Release | `powershell -ExecutionPolicy Bypass -File .\VENPOD\build.ps1 -Config Release` | `VENPOD/build/bin/VENPOD.exe` is refreshed. |
| CPU/unit coverage | `ctest --test-dir .\VENPOD\build -C Release --output-on-failure` | `VENPODSparseCore` passes. |
| Full sparse gate | `powershell -ExecutionPolicy Bypass -File .\VENPOD\sparse_regression.ps1 -Config Release` | Public review docs/artifacts/file links/Markdown anchors, source-artifact tracked/staged git visibility, generated-artifact ignore patterns, and public PowerShell script parsing are verified before build; dense fallback smoke positively verifies dense backend selection, disabled sparse raymarch, and dense dispatcher wiring; default sparse render smoke verifies sparse-brick rendering with dense streaming/init bypassed; all sparse smokes pass, including edit persistence, physics, normal/stress engine capture, capture terrain ownership, and public demo capture validation; invalid capture parameters fail before build and runtime logs are scanned for failure markers. |
| Run the public sparse sandbox | `cd VENPOD; .\rebrun.ps1` | Launcher opens with sparse surface-authoritative sandbox as the default demo path. |
| Compare dense legacy | `cd VENPOD; .\rebrun.ps1 -DenseLegacy` | Old dense renderer remains available for fallback/regression comparison; the full sparse gate also proves the dense backend is active while sparse raymarch and sparse feedback/physics paths stay off. |
| Save/load sparse edits | `cd VENPOD; .\rebrun.ps1 -SparseEditFile saves\review-edits.vsed` | Sparse edits load on startup and save on shutdown. |
| Generate public media | `cd VENPOD; .\public_demo_capture.ps1 -Config Release` | Validated contact sheet, stats, runtime log, and probed/decoded MP4 are generated under `VENPOD/build/captures/public_demo/`. |
| Generate public review reel | `cd VENPOD; .\public_demo_capture.ps1 -Config Release -ReviewReel` | Validated normal, high-flight, and waterline/submerged segments are combined into `sparse-public-review-reel.mp4` with per-segment contact sheets/logs, `review_reel_manifest.csv`, and `PUBLIC_DEMO_REVIEW_REEL.md`. |
| Generate visual review suite | `cd VENPOD; .\visual_review_capture.ps1 -Config Release` | Validated normal, walk, long-walk, fast-flight, long-fast-flight, fast water-transition, long fast-water transition, waterline, and long-waterline contact sheets plus `VISUAL_REVIEW_CHECKLIST.md` and `VISUAL_REVIEW_SUMMARY.csv` are generated under `VENPOD/build/logs/visual_review_capture/` for manual public-readiness review. |

## Known Review Limits

- Dense legacy remains in the repository for fallback and comparison.
- GPU brush feedback and GPU physics proposal application remain guarded hybrid
  paths; CPU sparse authority remains the fallback.
- Mid/far terrain passes coverage and ownership gates, but final long-distance
  LOD polish remains future work.
- Generated MP4 and smoke artifacts are not tracked in git.
